SquareDoom — project_y / paint perf learnings
=============================================
(E1M1 spawn / similar poses; PROFILE HUD P = project_y cycle sum)

What the histograms showed
--------------------------
- Most project_y calls: n = 2..7 adds; |Δh| targets mostly 1..5.
- Large-n tails are rare on typical E1M1 views.
- |Δh| is world height vs eyeheight, not on-screen wall size.
- Walls do not call project_y (only ceil/floor near + portal flats).

What helped P
-------------
- Lo-only sum when texstep_h=0: keep A=acc_l; DEC (up) / INC (down)
  signed remaining Δh on carry until 0 — no absolute value on that path.
- Hi / one-step: need a positive CMP target. Going_up already has Δh>0;
  going_down takes |Δh| once into tmp1 only when texstep_h≠0, then the
  same cheap `cmp` per iter (avoids per-iter `tmp3+acc_h` when down).
- Polarity walk: start X=HORIZON; DEX (Δh>0) / INX (Δh<0) each add;
  stop on coverage or screen edge 0/25; py_row=X. Drops the cheap
  post-sum HORIZON±n epilogue and free-stops at screen rails.
  Measured ~P $01E1 on the same style of pose (better than sum+epilogue).
- Callers still clamp_span against ytop/ybot after project_y.

What hurt or was not worth it
-----------------------------
- Always using exact 16÷8 for “distant” / long-n: tax dominates because
  short-n calls are the common case → N/P worse; reverted.
- Hybrid probe then 16÷8 (PY_PROBE=8): P rose ~$224 → ~$282; reverted.
- Fill span unroll ×4: first attempt broke empty-span semantics / tmp1;
  “safe” variant was slower; keep simple (zp),Y fill.
- Self-mod STA abs,Y fill: tiny win, not worth complexity.
- In-loop stop on ytop/ybot each add: correct and can skip dead iters
  past a tight clip, but per-iter CPX+branch (~5–8 cy) on every add.
  With hist (short n, first paint usually ytop=0/ybot=25) you almost
  never early-exit → pure tax vs one post clamp_span. Do not prioritize
  as a P win; if retested, gate behind a build flag and compare P.
- Incremental project_y (min(|h−eye|, |h−h_ref|) from last row at same
  texstep): theoretically good for small ledges, but preamble (ref ok,
  two abs, compare) taxes every call. Short-n / single-project / first-
  at-wallz cases dominate → worst-case P worse; reverted. Do not revive
  without a caller-gated “second height at this wallz” path that skips
  the min check on the common first project.

Profiling pitfalls
------------------
- Column setup (HUD S): world-byte player (frac=(world&7)<<5); 16-bit
  fixsec/dd + mid(16×8) calc_sdx/sdy. 8-bit fixsec crushed near-axis
  variation and broke TheKeep wallz — reverted. sintab amp=2. Remaining S
  is mostly 2× mid-products × 40 columns.
- prof_add_bucket must not touch paint tmp* (tmp4/tmp5 etc.). Use
  dedicated ZP (prof_now_*, prof_dt_*). Clobbering tmp mid-paint
  silently broke the frame.
- HUD F is always on (even PROFILE=0): frame ms via cascade timers.
  PROFILE=1: S D W N L P (W=wallz). PROFILE=0: F + C (fill_span count).
  Bucket ms ≈ (cycles>>8)/4, 3 digits (JSW-Tape PrintDec3). Clamp 999.
  fps ≈ 1000 / F.
- F = full loop via CIA2 Timer B cascaded off Timer A (32-bit).
- Consistency check: F should be ≥ S+D+W+N+L+P (miss blit/input/gaps).
- Labels: build with --vicelabels + tools/sort_lbl.py (Deathchase-style).
- PROFILE=1 bucket hooks add ~160 ms/frame vs F-only; use F without
  PROFILE for real fps, PROFILE for relative region costs.
- Same-flat skip: if cur SEC_FLOOR/CEIL/FCOL/CCOL match last paint_near
  this column, skip load+paint_near (untextured — deeper same heights only
  move outward vs horizon, fills already no-ops). If next needs a portal
  ledge, still refresh_near_spans (span_a/b at current wallz).
- N ≈ near fills + bookkeeping (not project_y — that is P). fill_span takes
  fill_y0/fill_y1 so paint_* need not PHA/PLA ytop/ybot around fills.
- Incremental fish wallz: TheKeep muls sdx*fish once per hit; we hit every
  portal. Cache mid(ddx/ddy*fish) in rebuild_col_rays; per column
  wz = mid(s*fish); each DDA step wz += dd*w. calc_wallz is >> only (W≈0).
  Slight mid-product drift vs remul each edge — acceptable for untextured.

Level / sector ids
------------------
- Map bytes store sector id directly; that id indexes the SoA attr tables
  (SEC_FLOOR[id], …). No extra indirection.
- Tables are 7×256 (id 0 unused). Cook fills only ids present in the
  editor Map; other slots stay 0 — sparse *usage*, fixed layout.
- Cook does not densify to 1..N. Editor allocSectorId takes lowest free
  1..255; deletes/splits leave holes, so E1M1 can show ~25 live sectors
  with ids like 1..22, 53, 108, 150. Portal dump “108” is a real tile id.

Portal clip / rising floors
---------------------------
- Flat ceil along a stair still shows orange bands when floors rise above
  eyeheight: project_y puts those floors above HORIZON, so lower-ledge
  risers paint in the upper half (easy to misread as a ceiling wall).
- Open portal after step-up is [ytop, farFloorY). Always ybot = farFloorY
  (even when that Y is above HORIZON). That aperture is the gap between
  ceiling and the raised floor surface.
- Wrong fix (reverted): if farFloorY < HORIZON then ytop = nearFloorY.
  On steps that straddle the horizon that snaps ytop to below-horizon
  nearFloorY and closes the clip (dump: 013 open → 008 015/015 stop)
  so only ~2 sectors appear when looking up stairs. Do not revive that.
- paint_near: if floor projects above HORIZON (floor > eye), still store
  span_b for ledges but do not fill floor-to-bottom or set ybot = that
  row — that made the floor join sit too high. Same guard in editor.
- Close look-up “raised wall”: dump ytop=2 is ceil (span_a), NOT farFloorY.
  Close vs pulled-back dumps barely differ (ybot 6 vs 7 after into 6). When
  near ceil clamps to ybot, must still fill [ytop,ybot) with ceil and close
  (editor ceilEnd > yTop). Old `cmp ybot / bcs skip` left a false opening;
  solid into void painted that band WALL_NS orange. Fix: allow ceil fill when
  clamp(ceil) == ybot.
- DBG_PORTAL line: id ytop ybot span_a span_b near_floor above_eye
  farFloorY texstep_h. farFloorY=$FF if not projected; span_b=$FF if floor
  skip. above_eye = 1 if near_floor > eyeheight. Do not read ytop as floor.
